# AI 私厨

面向日常家庭饮食场景的多模态 AI 食谱助手。用户可以输入现有食材，或上传食材照片，通过连续对话获取菜谱建议，并查看、继续或删除历史料理记录。

项目将多模态模型、联网检索和会话持久化接入完整的 Web 应用，覆盖从食材输入、图片上传、智能体调用，到流式展示与历史管理的端到端流程。

## 功能概览

| 功能 | 实现方式 |
| --- | --- |
| 文字与图片输入 | 支持食材清单和图片提问，图片通过 OSS 预签名地址上传 |
| 智能食谱推荐 | 多模态模型理解食材，智能体调用 Tavily 检索公开菜谱 |
| 推荐依据 | 提示词引导模型结合营养与制作难度，整理推荐理由与做法 |
| 流式对话 | FastAPI 返回增量文本，React 前端逐步展示回答 |
| 历史查看与续聊 | 从服务端 SQLite checkpoint 恢复会话和消息，包括图片内容 |
| 历史删除 | 确认后删除指定会话的 checkpoint 与 writes，保留其他会话 |
| 自适应界面 | React 实现桌面布局、移动端侧栏、Markdown 展示与图片预览 |

## 技术架构

```text
React 前端
  ├─ 文字提问 / 图片选择 / 流式展示
  └─ 历史列表 / 消息恢复 / 删除确认
               │
           FastAPI 接口
               │
        LangChain 智能体
          ├─ 多模态大模型
          ├─ Tavily 菜谱检索
          └─ LangGraph SQLite 会话记忆

图片上传：浏览器 → OSS 预签名 PUT → 图片地址 → 多模态模型
```

## 工程实现

- **前后端分离与单服务部署**：开发时使用 Vite 代理后端接口，构建后由 FastAPI 托管 React 静态资源。
- **服务端会话历史**：历史列表读取持久化 checkpoint，不依赖浏览器本地存储；使用 `thread_id` 区分对话上下文。
- **受控会话删除**：前端提供二次确认，后端使用会话锁避免生成与删除同时进行。
- **直接上传图片**：通过预签名 URL 将图片上传到 OSS，浏览器不持有长期云凭据；前端校验图片类型和大小。
- **交互与异常反馈**：支持输入法兼容、快捷问题、上传状态、错误提示以及停止读取回答。
- **输出可读性**：使用 React Markdown 与 GFM 展示列表、表格、步骤及链接，不启用模型输出中的原始 HTML。

营养与难度评估由模型根据提示词生成，尚未经过专业营养评估验证。项目未声称具有线上用户规模或生产级服务指标。

## 技术栈

前端：React、Vite、React Markdown、Lucide。

后端：Python、FastAPI、LangChain、LangGraph、SQLite、Tavily、阿里云 OSS、OpenAI 兼容模型接口。

## 本地体验

环境要求：Python 3.13+、Node.js 18+、uv。复制 `.env.example` 为 `.env`，配置模型服务、Tavily 和 OSS。使用图片上传时，OSS 需允许前端来源进行跨域 PUT 请求。

启动后端：

```bash
uv sync
uv run uvicorn app.main:app --host 127.0.0.1 --port 8001
```

另开终端启动前端：

```bash
cd frontend
npm ci
npm run dev
```

访问终端显示的前端地址，默认 `http://127.0.0.1:5173`。接口文档位于 `http://127.0.0.1:8001/docs`。

如需由后端统一提供页面，执行 `npm run build` 后访问后端地址。仓库包含前端源码和依赖锁文件，不包含密钥、数据库、真实会话、日志或依赖目录。

## 验证与应用边界

已通过 React 生产构建与离线接口测试，覆盖历史读取、指定会话删除、其他会话保留、生成期间删除保护及模拟文本流。测试结果不等同于真实模型回答质量、OSS 上传可用性或线上性能验证。

当前为单用户应用演示。`thread_id` 用于区分会话，不代表用户权限隔离；公开部署需补充身份认证、会话归属校验和限流。停止按钮中止前端读取，不保证立刻取消服务端模型调用；删除会话不会自动清理 OSS 图片。

食谱建议仅供参考，涉及过敏、疾病饮食或特殊营养需求时，应咨询专业人士。
